包详情页统一结构：3 种布局方案

目标：默认降低历史版本和多文件噪声，同时保留快速下载、复制依赖配置、查看全部版本的效率。

A. 推荐：概览 + 当前版本主卡 + 抽屉
Breadcrumb / Package type / Delete
包概览：名称、描述、latest、下载量、仓库
当前版本卡：版本号、状态、主文件、安装命令、复制按钮
包信息侧栏：GAV / registry / license / protocol fields
文件摘要：主文件 + “展开全部文件”

A. 当前版本优先

主界面聚焦 latest/selected version；历史版本进入抽屉。最适合 Maven/SNAPSHOT，也适合所有协议统一。

B. 中间方案：保留小型版本列表
包概览
当前版本 + 安装说明
最近 5 个版本列表
文件列表折叠区

B. 最近版本可见

仍能一眼看到几个历史版本，但页面比现在清爽。缺点是 Maven 文件噪声仍可能占空间。

C. Tab 方案：分区明确
包概览
Tab: 使用方式 | 文件 | 版本历史 | 安全
当前 Tab 内容

C. Tabs 分区

结构清楚、扩展性好；缺点是主要信息被隐藏到 Tab 后，首次使用路径更长。

我的推荐：A

  • 最能解决“展示太多”的问题
  • 不破坏已有 VersionTable，可改成抽屉复用
  • 符合所有协议：版本是主对象，文件和历史是次级细节

需要注意

  • 管理员操作入口要保留在版本抽屉中
  • 当前版本卡要清楚展示“已缓存/未缓存”
  • Maven SNAPSHOT 需要显示逻辑版本，不平铺 timestamp build
